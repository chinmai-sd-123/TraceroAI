## The context manager

`client.trace()` is the one to use in most code. It times the block, measures each step
from when you log it (so log each piece right after the work it records), marks the
answer as unanswered if an exception escapes, and sends the trace when the block ends.
`t.trace_id` is set as soon as the block starts. Your exception is never swallowed, and
a failure to send never raises.

## What to log

- **Retrieval**: the chunks your retriever returned, in order. See
  [Retriever output and chunks](/docs/instrument/chunks).
- **Prompt** (optional): log a `version` and grounding failures from one prompt are
  grouped as [one issue](/docs/concepts/issues).
- **Generation**: the answer and the model. Pass `prompt_tokens` and
  `completion_tokens` and the server works out the cost.
- **Metadata** (optional): anything you'll want to filter or group by later.

You don't send evaluations or a diagnosis; the server computes them.

## Redacting sensitive data

Give the client a `redact` function to remove personal data before anything leaves your
application. It receives a copy of each trace (the JSON that `POST /v1/traces` takes) and
returns the trace to send, or `None` to drop it:

```python
from traceroai import TraceroClient
from traceroai.redaction import mask_emails, redact_strings

client = TraceroClient(redact=redact_strings(mask_emails))
```

`redact_strings` applies a text function to every string that can hold user text: the
question, the retrieved chunks, the prompt, the answer and metadata. Ids, timestamps,
model names and the project are left alone. Write your own for anything else, such as
phone or account numbers.

It runs before a trace is queued, so unredacted text never waits in the send queue. If
the function raises, or returns something other than a dict or `None`, the trace is
dropped, never sent unredacted, and counted in `client.redaction_failures`. The trace id
can't be changed by it, so retries stay safe. `AsyncTraceroClient` takes the same
argument.

## Read a trace back

```python
trace = client.get_trace(t.trace_id)
trace["diagnosis"]["label"]        # e.g. "retrieval_miss"
trace["generation"]["usage"]       # tokens and cost_usd
```

`get_trace` waits for queued traces to send first, so a trace you just logged can be
read straight away.
