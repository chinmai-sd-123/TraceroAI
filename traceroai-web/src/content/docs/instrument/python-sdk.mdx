## The context manager

`client.trace()` is the one to use in most code. It times the block, measures each step
from when you log it (so log each piece right after the work it records), marks the
answer as unanswered if an exception escapes, and sends the trace when the block ends.
`t.trace_id` is set as soon as the block starts. Your exception is never swallowed, and
a failure to send never raises.

## What to log

- **Retrieval**: the chunks your retriever returned, in order. See
  [Retriever output and chunks](/docs/instrument/chunks).
- **Prompt** (optional): log a `version` and grounding failures from one prompt are
  grouped as [one issue](/docs/concepts/issues).
- **Generation**: the answer and the model. Pass `prompt_tokens` and
  `completion_tokens` and the server works out the cost.
- **Metadata** (optional): anything you'll want to filter or group by later.

You don't send evaluations or a diagnosis; the server computes them.

## Read a trace back

```python
trace = client.get_trace(t.trace_id)
trace["diagnosis"]["label"]        # e.g. "retrieval_miss"
trace["generation"]["usage"]       # tokens and cost_usd
```

`get_trace` waits for queued traces to send first, so a trace you just logged can be
read straight away.
